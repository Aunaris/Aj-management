# 2D Animation Classroom Management System

ระบบ **เช็คชื่อ ส่งงาน และให้คะแนนระหว่างคาบ** สำหรับรายวิชา **10802103 การสร้างภาพเคลื่อนไหวด้วยเทคนิคภาพ 2 มิติ** (ภาคการศึกษา 1/2569 มหาวิทยาลัยแม่โจ้)
พัฒนาตาม *System Blueprint v1.2* และข้อมูลรายวิชาจาก *OBE-3*

## เริ่มใช้งาน

ต้องใช้ Node.js 20 ขึ้นไป

```bash
npm install
npm run seed -- --demo   # (ไม่บังคับ) สร้างข้อมูลตัวอย่าง: นักศึกษา 10 คน + งาน Bouncing Ball
npm start                # http://localhost:3000
npm test                 # ชุดทดสอบอัตโนมัติ (อิง Test Cases TC-01–TC-30)
```

เมื่อรันครั้งแรก ระบบจะสร้างข้อมูลรายวิชาจาก OBE-3 ให้อัตโนมัติ ได้แก่ CLO1–CLO4, โครงสร้างคะแนน 100 คะแนน และแผนการสอน 17 สัปดาห์

| บัญชีเริ่มต้น | ชื่อผู้ใช้ / รหัสผ่าน |
|---|---|
| Admin | `admin` / `admin1234` |
| อาจารย์ทักษิณ อินตะพิงค์ | `thaksin` / `teacher1234` |
| ผศ.พิริยะ กาญจนคงคา | `piriya` / `teacher1234` |
| นักศึกษา (หลังนำเข้า) | รหัสนักศึกษา / รหัสนักศึกษา |

ทุกบัญชีถูกบังคับให้เปลี่ยนรหัสผ่านเมื่อเข้าสู่ระบบครั้งแรก ยกเว้นข้อมูลที่สร้างด้วย `--demo` ส่วนรหัสผ่านเริ่มต้นตั้งได้ผ่าน `ADMIN_PASSWORD` และ `TEACHER_PASSWORD`

## กลุ่มเรียน (Section)

ระบบแบ่งการจัดการเป็นกลุ่มเรียน (ค่าเริ่มต้น 3 กลุ่ม) แต่ละกลุ่มมีรายชื่อ คาบเรียน 17 สัปดาห์ การเช็คชื่อ และรายงานแยกกัน ส่วนงานที่มอบหมาย Rubric และโครงสร้างคะแนน OBE-3 ใช้ร่วมกันทุกกลุ่ม

- **นำเข้ารายชื่อ**: เมนู *นักศึกษา* → อัปโหลดไฟล์ `ClassRoster_xxxxx.csv` จากระบบทะเบียน
  - เลือกได้หลายไฟล์พร้อมกัน ระบบอ่านกลุ่มเรียนจากหัวไฟล์
  - เก็บสาขาวิชาและคณะด้วย
  - ถ้ายังไม่มีกลุ่มนั้น ระบบจะสร้างกลุ่มพร้อมคาบเรียนให้อัตโนมัติ
  - รองรับไฟล์ UTF-8 และ Windows-874
  - นำเข้าซ้ำได้: ระบบอัปเดตชื่อและกลุ่ม ไม่สร้างบัญชีซ้ำ
- **เลือกกลุ่มที่จัดการ**: ใช้ตัวเลือกที่มุมขวาบน ทุกหน้าจะกรองตามกลุ่มที่เลือก ได้แก่ Dashboard, คาบเรียน, นักศึกษา, ตรวจงาน, Quick Grid, สมุดคะแนน, CLO และรายงาน
  - เลือก "ทุกกลุ่ม" เพื่อดูรวม รายงานจะมีคอลัมน์ "กลุ่ม"
- **ตั้งตารางเรียน**: เมนู *กลุ่มเรียน (Section)*
  - ตั้งวันเรียนสัปดาห์ที่ 1, เวลา และห้องของแต่ละกลุ่ม
  - ระบบเลื่อนวันที่ของคาบที่ยังไม่เริ่มเช็คชื่อให้ตรงตารางนี้
- **เช็คชื่อ**:
  - QR ของคาบใช้ได้เฉพาะนักศึกษาในกลุ่มนั้น
  - นักศึกษาเห็นเฉพาะคาบของกลุ่มตนเอง
  - เมื่อปิดคาบ นักศึกษาที่ไม่ได้เช็คชื่อจะถูกบันทึกเป็นขาดเรียนเฉพาะในกลุ่มนั้น
- **ย้ายกลุ่ม**: ทำได้ที่หน้ารายละเอียดนักศึกษา ประวัติการเข้าเรียนเดิมยังอยู่

> ไฟล์รายชื่อนักศึกษาเป็นข้อมูลส่วนบุคคล อย่า commit ลง git — นำเข้าผ่านหน้าเว็บ (ข้อมูลอยู่ใน `data/` ซึ่งไม่ถูก commit)

## การใช้งานระหว่างคาบ (สำหรับอาจารย์)

1. **Dashboard → "เปิดคาบ + QR"** หรือเลือกคาบที่เมนู *คาบเรียน & เช็คชื่อ*
2. กด **"เปิดจอ QR (Projector)"** เพื่อแสดง QR บนโปรเจกเตอร์
   - QR เปลี่ยนใหม่ทุก 45 วินาที (ตั้งค่าได้)
   - ใต้ QR มีรหัส 6 ตัว สำหรับนักศึกษาที่สแกนไม่ได้
3. รายชื่อในหน้าระหว่างคาบอัปเดตอัตโนมัติ
   - คลิก *มาเรียน / มาสาย / ขาดเรียน / ลา* เพื่อบันทึกแบบ Manual
   - การแก้สถานะที่บันทึกไปแล้วต้องระบุเหตุผล
4. **"สุ่มรหัสยืนยันในห้อง"** สร้างรหัส 4 หลักอายุ 2 นาที ให้นักศึกษากรอกยืนยันว่าอยู่ในห้องจริง
5. **Quick Grid** ให้คะแนนทั้งห้องในหน้าเดียว
   - พิมพ์คะแนนแล้วระบบบันทึก Draft อัตโนมัติ
   - กด Enter เพื่อลงไปแถวถัดไป
   - กด "เผยแพร่" เพื่อให้นักศึกษาเห็นคะแนน
6. **ตรวจงาน**: รายชื่อ, Preview (ภาพ, GIF, วิดีโอ) และ Rubric อยู่ในหน้าเดียวกัน
   - บันทึก Draft, เผยแพร่ หรือขอให้แก้ไข พร้อม Feedback
7. **ปิดเช็คชื่อ**: นักศึกษาที่ยังไม่เช็คชื่อจะถูกบันทึกเป็น "ขาดเรียน" (แก้ไขภายหลังได้ โดยระบุเหตุผล)

## ตรวจตำแหน่ง GPS / IP / อุปกรณ์ตอนเช็คชื่อ

ตั้งค่าที่เมนู *ตั้งค่ารายวิชา → ป้องกันการเช็คชื่อแทน*

- **1 เครื่อง เช็คชื่อได้ 1 คนต่อคาบ** (เปิดเป็นค่าเริ่มต้น)
  - ระบบจำเครื่องจาก Device ID ใน cookie และ localStorage ของเบราว์เซอร์
  - บัญชีที่สองที่ใช้เครื่องเดียวกันจะถูกปฏิเสธ และระบบสร้าง Risk Event ให้ผู้สอนตรวจ
  - ผู้สอนยังบันทึกแบบ Manual ให้ได้เสมอ เช่น กรณีนักศึกษาไม่มีโทรศัพท์
- **GPS**
  - ผู้สอนกด "📍 ใช้ตำแหน่งเครื่องนี้เป็นจุดห้องเรียน" ที่หน้าระหว่างคาบ หรือกรอกพิกัดในหน้าตั้งค่า
  - นักศึกษาต้องอนุญาต Location และต้องอยู่ในรัศมีที่กำหนด (ค่าเริ่มต้น 150 ม.)
  - ถ้าตำแหน่งคลาดเคลื่อนเกินเกณฑ์ ระบบจะให้ลองใหม่
  - ระบบบันทึกระยะห่างจากห้องเรียนไว้ และลบพิกัดดิบหลัง 30 วัน
- **IP**
  - บันทึก IP ทุกครั้งที่เช็คชื่อ
  - จำกัดได้ว่าต้องเช็คชื่อจากเครือข่ายมหาวิทยาลัย โดยกรอก CIDR เช่น `202.28.10.0/24`
  - ใช้ IP แยกเครื่องไม่ได้ เพราะนักศึกษาที่ใช้ Wi-Fi เดียวกันจะมี IP สาธารณะเดียวกัน
- **ลักษณะเบราว์เซอร์ (fingerprint) ซ้ำกับบัญชีอื่น**: แจ้งเตือนระดับต่ำเท่านั้น ไม่ปฏิเสธ เพราะมือถือรุ่นเดียวกันอาจให้ค่าเหมือนกัน

> ⚠️ เบราว์เซอร์ขอตำแหน่ง GPS ได้เฉพาะเว็บที่เปิดผ่าน **HTTPS** (ยกเว้น localhost)
> ถ้า deploy หลัง reverse proxy ต้องตั้ง `TRUST_PROXY=1` เพื่อให้ระบบได้ IP จริงของนักศึกษา
> ข้อจำกัด: ทุกมาตรการข้างต้นยังหลบเลี่ยงได้ เช่น ใช้แอปปลอมตำแหน่ง GPS หรือใช้เบราว์เซอร์คนละตัว จึงควรใช้คู่กับการสุ่มรหัสยืนยันในห้องและการตรวจของผู้สอน

## รับงานทางอีเมล

ใช้งานที่เมนู *รับงานทางอีเมล* (เฉพาะอาจารย์)

1. **เชื่อมกล่องอีเมลของอาจารย์ผ่าน IMAP**
   - Gmail / Google Workspace ให้ใช้ App Password
   - ระบบเข้ากล่องอีเมลแบบอ่านอย่างเดียว ไม่ลบ ไม่ย้าย และไม่ทำเครื่องหมายว่าอ่าน
   - App Password เก็บแบบเข้ารหัสด้วย `APP_SECRET` หรือไฟล์ `data/secret.key` ที่สร้างอัตโนมัติ
2. **ระบบตรวจอีเมลใหม่ทุก 5 นาที** (ตั้งค่าได้) หรือกด "ตรวจอีเมลตอนนี้"
3. **นักศึกษาส่งอีเมล** โดยตั้งหัวเรื่อง `[A01] 6501101001 ชื่อ` แล้วแนบไฟล์ หรือวางลิงก์ Drive/YouTube ในเนื้อหา
   - ระบบสร้างการส่งงานให้อัตโนมัติ
   - ใช้เวลาที่อีเมลถึงเซิร์ฟเวอร์เป็นเวลาส่ง
   - ใช้เงื่อนไขเดียวกับการส่งผ่านเว็บ ได้แก่ ชนิดไฟล์ ขนาด จำนวนครั้ง และการส่งล่าช้า
4. **อีเมลที่ระบบจับคู่ไม่ได้ หรือไม่ผ่านเงื่อนไข** จะอยู่ในกล่อง "รอจัดการ" ให้อาจารย์เลือกนักศึกษาและงาน แล้วกดนำเข้าเอง
5. **อีเมลอื่นที่ไม่เกี่ยวกับรายวิชาจะไม่ถูกบันทึก**
   - ระบบเก็บเฉพาะอีเมลที่ส่งจากอีเมลนักศึกษาในรายวิชา
   - หรือหัวเรื่องมีรหัสวิชา รหัสงาน หรือรหัสนักศึกษา
6. **Microsoft 365 ระดับองค์กร** ส่วนใหญ่ปิดการเข้าสู่ระบบด้วยรหัสผ่านทาง IMAP แล้ว และรุ่นนี้ยังไม่รองรับ OAuth ให้ตั้ง Forward อีเมลไปที่ Gmail แทน

## สถาปัตยกรรม

- **Express 5 + EJS** แบบ Server-rendered และ Responsive
- **SQLite** (better-sqlite3)
  - schema ตาม Blueprint หมวด 7 และใช้ UUID เป็น Primary Key จึงย้ายไป PostgreSQL ได้
- **ไฟล์งาน** เก็บแยกจากฐานข้อมูลใน `storage/` ผ่าน `src/services/storage.js`
  - เปลี่ยนเป็น S3-compatible storage ได้โดยเขียน driver ใหม่
- โครงสร้างโค้ด:
  - `src/services/` — business logic
  - `src/routes/` — HTTP
  - `views/` — หน้าจอ
  - `test/` — ชุดทดสอบ

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` | 3000 | พอร์ต |
| `BASE_URL` | จาก request | URL ที่ฝังใน QR (ควรตั้งเมื่ออยู่หลัง proxy) |
| `DB_FILE` | `data/classroom.db` | ไฟล์ฐานข้อมูล |
| `STORAGE_DIR` | `storage/` | ที่เก็บไฟล์งาน |
| `MAX_UPLOAD_MB` | 500 | ขนาดไฟล์อัปโหลดสูงสุดของระบบ |
| `COOKIE_SECURE=1`, `TRUST_PROXY=1` | — | ใช้เมื่อ deploy หลัง HTTPS reverse proxy |
| `APP_TZ_OFFSET` | `+07:00` | เขตเวลา |
| `APP_SECRET` | ไฟล์ `data/secret.key` | กุญแจเข้ารหัสรหัสผ่านอีเมล |

## ประเด็นที่ยังต้องยืนยัน (Blueprint หมวด 13)

ระบบตั้งค่าเริ่มต้นไว้แล้ว แต่ผู้สอนควรตรวจสอบประเด็นต่อไปนี้:

- **วันที่ของแต่ละคาบ**: seed เริ่มสัปดาห์ที่ 1 วันที่ 15 มิ.ย. 2569 เวลา 09:00–13:00 (ตั้งได้ผ่าน `SEED_START_DATE`) ควรแก้ให้ตรงตารางจริงที่หน้าแก้ไขคาบ
- **เกณฑ์มาสาย**: 15 นาที
- **อายุ QR**: 45 วินาที
- **เกณฑ์ผ่าน CLO**: ยังไม่กำหนด
- **การยืนยันโครงสร้างคะแนน**: ต้องกดยืนยันที่ *ตั้งค่ารายวิชา* ก่อนเปิดใช้งาน
- **การจัดสรรคะแนนเป็นรายงาน**: ใช้ Template เป็นค่าเริ่มต้น และปรับได้
